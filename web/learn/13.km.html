Lab៖ labs/09-production

Checklist មុន deploy «real»

  1. Pin versions — postgres:16-alpine មិនមែន postgres:latest។ Labs ដើមប្រើ series tag (redis:7-alpine, node:22-alpine, nginx:1.28-alpine)។ Labs CRITICAL-gated / គិតបែប production pin digest (FROM node:22-alpine@sha256:… ក្នុង Labs 05, 08 slim, 09, 12, និង 13; Postgres/Redis ក្នុង Lab 13 Compose — Lab 05 Compose នៅ float tags ទាំងនោះដោយចេតនា)។ ជំពូក 15 ពន្យល់ tag vs digest។
  2. Non-root user — USER node or custom UID
  3. Read-only root filesystem where possible (--read-only + writable tmp mounts)
  4. Healthchecks — Alpine Node images ភាគច្រើនគ្មាន wget/curl។ Probe ដោយ Node runtime ដូច app:
HEALTHCHECK --interval=15s --timeout=3s --start-period=5s --retries=3 \
  CMD node -e "fetch('http://127.0.0.1:3000/health').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"

healthcheck:
  test:
    [
      "CMD",
      "node",
      "-e",
      "fetch('http://127.0.0.1:3000/health').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))",
    ]
  interval: 15s
  timeout: 3s
  retries: 3
  start_period: 5s
  1. Resource limits — Compose V2 (docker compose) apply deploy.resources លើ single node។ មិនត្រូវការ Swarm ឬ key ចាស់ mem_limit / cpus។
deploy:
  resources:
    limits:
      cpus: "0.50"
      memory: 256M
  1. Restart policy
restart: unless-stopped
  1. Init process — init: true (ឬ docker run --init) ដើម្បីឱ្យ PID 1 reap zombies និង forward SIGTERM ពី docker stop។ គូជាមួយ exec-form CMD និង graceful shutdown ក្នុង app។
init: true
  1. Logging — don't log secrets; ship logs collector; cap Docker json-file logs ដើម្បីកុំឱ្យ app សរសេរពេញថាស។
logging:
  driver: json-file
  options:
    max-size: "10m"
    max-file: "3"

  1. One process per container (guideline) — app one, db another; use Compose/K8s compose them.

  2. Immutable images — rebuild redeploy; don't «hotfix» running containers.

  3. Publish នៅ localhost ពេល reverse proxy នឹង terminate TLS — 127.0.0.1:3000:3000 ដើម្បីកុំឱ្យ API លេចនៅគ្រប់ interface របស់ host។ Lab 09 និង Compose prod របស់ Lab 12 ធ្វើបែបនេះ។

  4. Drop Linux capabilities — cap_drop: [ALL] (ឬ docker run --cap-drop ALL) ដើម្បីកុំឱ្យ process ទទួលសិទ្ធិ kernel ដែលវាមិនត្រូវការ។ គូជាមួយ no-new-privileges។

Restart policies (ច្បាប់ restart)

Policy Behavior
no Never restart
always Always restart
on-failure Restart on non-zero exit
unless-stopped Always, except manually stopped
